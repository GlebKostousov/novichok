# Новичок

Решение тестового задания про адаптацию новых сотрудников в магазине спорттоваров.

Анна выходит на работу продавцом. Покупатель ищет кроссовки для зала до 6 000 ₽. В приложении можно ответить за Анну, вернуть ей ответ на доработку и решить, готова ли она консультировать покупателей сама.

## Ответ на задание

1. Выбрал адаптацию продавца: подбор товара, проверка наставника и допуск к самостоятельным консультациям.
2. Причины уходов неизвестны. Указанная в задании треть относится к ушедшим сотрудникам.
3. Сделал путь от первого дня через ответ покупателю и совместную практику до допуска.
4. Наставник возвращает ответ с замечанием и принимает доработку по трём критериям.
5. Руководитель выделяет время наставника для Милы и определяет границы самостоятельной работы Анны.
6. Повтор события выхода сохраняет одного сотрудника и его прогресс.
7. Все данные вымышлены. У посетителей отдельные учебные примеры; черновики сохраняются.
8. Использовал Python, FastAPI, PostgreSQL, Svelte и TypeScript.
9. Проверил правила сервера через pytest: по 50 успешных тестов на SQLite и PostgreSQL; сценарии в Chromium через Playwright: 20 успешных проверок.
10. Проверил сохранение ответов, черновиков и решения руководителя после обновления страницы, повтор события и независимость примеров посетителей.
11. Вход, Битрикс24 и уведомления отложил, чтобы закончить цикл сотрудник → наставник → руководитель.
12. Неудачная практика и отказ в допуске не реализованы. Нагрузка, другие браузеры и влияние на удержание не проверялись. Следующим шагом выяснил бы, где новичкам нужна помощь и сколько времени на неё есть у наставников.
13. После ревью 11 ноября я доработал демо. Сколько часов заняла первая версия, по архиву установить нельзя.

## Как проверить содержимое репозитория

На странице GitHub нажмите **Code → Download ZIP** и распакуйте архив. В нём есть:

- `frontend/public/presentation.html` — презентация из десяти слайдов. Откройте файл в браузере; для просмотра приложение запускать не нужно.
- `frontend/public/demo.webm` — запись полного сценария, 57 секунд. Откройте её в браузере или видеоплеере.
- `backend/` и `frontend/src/` — код приложения.
- `backend/tests/` и `frontend/e2e/` — автоматические проверки правил и действий пользователя.

В презентации объяснены выбор задачи, допущения и план проверки результата. В записи показаны ответ Анны, замечание наставника, доработка, практика и допуск руководителя.

## Как запустить приложение из этого репозитория

Нужны Docker с Docker Compose и Python 3. Откройте терминал в распакованной папке проекта и выполните:

```bash
python scripts/configure.py
docker compose up --build -d
```

После запуска откройте **http://127.0.0.1:8080/**. Первая сборка скачивает необходимые пакеты и может занять несколько минут. На системах, где Python вызывается командой `python3`, используйте её в первой строке.

### Что проверить в приложении

1. Выберите роль **«Сотрудник»** и **Анну Синицыну**. Прочитайте ситуацию покупателя и нажмите **«Свериться с каталогом»**.
2. Напишите, какие кроссовки вы предложите и почему. Нажмите **«Отправить наставнику»**.
3. В задании Анны нажмите **«Проверить в роли наставника»**. Напишите конкретное замечание и нажмите **«Вернуть с замечанием»**.
4. Кнопкой внутри задания откройте роль сотрудника. Доработайте ответ и отправьте его ещё раз.
5. Снова откройте проверку в роли наставника, отметьте все три критерия и нажмите **«Подтвердить задание»**.
6. Нажмите **«Перейти к следующему этапу»**. Отметьте действия Анны, напишите результат и нажмите **«Подтвердить практику»**.
7. Ещё раз перейдите к следующему этапу. В задании Анны нажмите **«Открыть в роли руководителя»**, опишите, какие консультации она может вести сама, и нажмите **«Подтвердить самостоятельность»**.
8. Обновите страницу, выберите Анну и откройте последний этап. Решение должно сохраниться, маршрут — показать четыре пройденных этапа.

Дополнительно можно проверить два случая. У **Милы Орловой** практике мешает отсутствие времени у наставника: руководитель сначала фиксирует устранение препятствия. В роли руководителя можно также добавить вымышленного новичка и нажать **«Повторить последнее событие»** — второго сотрудника не появится.

Чтобы проверить черновик, начните ответ, дождитесь надписи **«Черновик сохранён на сервере»** и обновите страницу. Кнопка **«Начать заново»** сбрасывает только ваш пример.

Роли переключаются для показа сценария. Личных учётных записей здесь нет; реальные персональные данные вводить не следует.

Если запускать приложение на своём компьютере неудобно, тот же сценарий доступен в [демонстрации](https://reportflow.ru/novichok). [Презентация онлайн](https://reportflow.ru/presentation.html) повторяет HTML-файл из архива.

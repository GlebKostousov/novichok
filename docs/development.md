# Разработка и проверки

Команды выполняются из корня проекта.

## Локальная разработка без Docker

Нужны Python **3.13**, `uv`, Node.js **22** и npm. Зависимости закреплены в
`backend/uv.lock` и `frontend/package-lock.json`.

```bash
make install
make run
```

Приложение: **http://127.0.0.1:8000/**, презентация:
**http://127.0.0.1:8000/presentation.html**. По умолчанию используется SQLite
в каталоге `backend`. `make run` собирает интерфейс, применяет миграции и
запускает сервер.

Для PostgreSQL экспортируйте строку подключения перед запуском:

```bash
export NOVICHOK_DATABASE_URL='postgresql+asyncpg://user:password@localhost:5432/novichok'
make run
```

Подставьте свои учётные данные. Для работы над интерфейсом можно отдельно
выполнить `npm run dev` в `frontend`: Vite перенаправляет `/api` на сервер
по адресу `127.0.0.1:8000`.

## Тесты и проверки

```bash
make check          # Ruff, форматирование, mypy, границы импортов, Svelte
make test           # Серверные тесты
make build          # Сборка интерфейса и копирование HTML-презентации
make test-delivery  # Проверка помощников запуска; не требует зависимостей API
```

Серверные тесты с PostgreSQL:

```bash
cd backend
TEST_DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/novichok_test uv run pytest
```

**Тесты очищают таблицы. Используйте отдельную тестовую базу, не базу демо.**

Браузерные проверки основного приложения выполняются против работающего стенда:

```bash
cd frontend
npx playwright install chromium
npm run test:e2e
```

`PLAYWRIGHT_BASE_URL` задаёт адрес стенда; по умолчанию это
`http://127.0.0.1:8000`. `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` позволяет указать
установленный Chromium. Сценарии выполняются на широком и узком экранах.

Для проверки Docker-сборки и запуска с чистой временной базой:

```bash
make verify-container
```

Нужны Bash, Python 3, Docker Engine, Compose v2 с `up --wait` и доступ к реестрам.
Команда использует отдельный Compose-проект, временный пароль и свободный
loopback-порт. После проверки удаляет только собственные контейнеры и volume;
рабочий `.env` не изменяет.

### Какие результаты подтверждены

Исходный отчёт разработки: 41 серверный тест на SQLite и те же 41 на PostgreSQL,
12 браузерных проверок. Это сохранённые результаты ранней версии.

Проверки исправлений 11 ноября 2026 года:

- Ruff lint/format, mypy strict, import-linter и Svelte check прошли; сборка обновлена.
- SQLite на Windows: 50 passed, один symlink-тест пропущен из-за отсутствия привилегии.
- PostgreSQL 17: 50 passed и один такой же skip в запуске с Windows.
- На Chromium прошли все 20 браузерных проверок на 1440×1000 и 390×844.
- Отдельно в Linux прошли symlink-проверка и все 7 тестов помощников запуска,
  включая Unix mode 0600; все 7 помощников также прошли на Windows.
- Записан основной цикл за 57 секунд: ответ, возврат, доработка, практика,
  решение руководителя и проверка результата после F5.

11 ноября 2026 года демо размещено на https://reportflow.ru/novichok. На публичном HTTPS-стенде прошли все 20 проверок Chromium на широком и узком экранах: основной цикл, сохранение после обновления страницы, изоляция учебных примеров и обработка ошибок. Презентация и видео также доступны.

Браузеры кроме Chromium, нагрузка и влияние на удержание не проверялись.

## Устройство проекта

```text
backend/
  app/core/           Настройки, база, транзакции, ошибки, логирование
  app/entities/       Сущности и правила маршрута
  app/workflows/      Составные сценарии демонстрации
  app/web/            HTTP-слой и раздача интерфейса
  migrations/         Миграции Alembic
  tests/              Серверные проверки
frontend/
  src/                Svelte / TypeScript
  public/presentation.html  Самостоятельная презентация
  e2e/                Браузерные сценарии приложения
scripts/              Настройка, запуск и проверка стенда
compose.yaml          Приложение и PostgreSQL
Dockerfile            Многоэтапная сборка
README.md             Как посмотреть и проверить демо
docs/                 Отчёт, разработка и размещение
```

HTTP-слой принимает запрос и передаёт его сервису. Правила находятся в
`entities`, составные действия — в `workflows`; репозитории работают с данными,
Unit of Work задаёт границу транзакции. Зависимости собирает фабрика приложения.
Конкурирующие изменения защищены проверкой версии. Повтор события выхода
обрабатывается по внешнему идентификатору внутри учебного примера.

## Автоматические проверки

GitHub Actions на каждом push в `main` и pull request запускает существующие проверки Python и Svelte, серверные тесты на SQLite, тесты помощников, сборку и браузерные сценарии Chromium на двух размерах экрана. PostgreSQL и Docker проверяются отдельными командами выше.
